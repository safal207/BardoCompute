# Bardo: когда сжатие стирает различие, необходимое для решения

Исследовательский отчёт • 5 сентября 2026 года

## Главное

На неизменённом коде Bardo воспроизведена граница четырёхсвидетельного представления HYBRID: четыре обычных ошибочных элемента способны вытеснить из передаваемых модели признаков пятую, критическую ошибку. Два разных состояния тогда имеют одинаковые входные признаки, но требуют противоположных ответов в синтетической задаче эскалации.

Это новый установленный результат для проверенной реализации. Мировая научная новизна, промышленная применимость и интерес инвесторов не установлены.

Обычная битовая маска решила ограниченный класс проверяемых запросов точно. Для него сериализованное представление занимает 9 байт вместо 205 байт полного набора результатов — на 95,61% меньше полезных данных. Это не универсальное сжатие без потерь, не выигрыш CPU/FPGA и не измеренная экономия денег.

## Что выполнено

Проверены 3 456 пар / 6 912 состояний: девять уровней фоновых ошибок, три начальных значения генератора, 128 пар на сочетание. В каждой паре совпадают общий состав и счётчики, меняется расположение одной ошибки. Ответ проверяется прямым просмотром критических позиций, независимо от сжатого представления.

| Фоновые ошибки, занимающие первые позиции | Пар с одинаковыми HYBRID-признаками и разными ответами |
|---|---:|
| 0, 1, 2, 3 | 0 из 384 на каждом уровне |
| 4, 5, 8, 16, 32 | 384 из 384 на каждом уровне |

RAW-признаки различают все построенные пары. Битовая маска отвечает правильно на всех этих состояниях. Отсутствие совпадений признаков на малой нагрузке не означает доказанную 100%-ную точность обученной модели: обучение здесь не проводилось.

Отдельная проверка всех 720 перестановок шести выбранных позиций дала 48 неразличимых пар при согласованном переносе области запроса. Это конечный эксперимент с размещением, не оценка частоты производственных отказов.

## Минимальная демонстрация

Все 71 позиции исходно нейтральны. Ошибки 18, 19, 20, 21 присутствуют в обоих состояниях. Ещё одна ошибка находится либо в обычной позиции 50, либо в критической позиции 60. Нумерация с нуля; критические позиции — 0–17 и 53–70.

Четыре выбранных свидетельства и глобальные счётчики совпадают. Поэтому совпадает именно вектор признаков, поступающий в модель. Равенство полного передаваемого пакета или корня целостности НЕ утверждается.

На сбалансированном наборе таких противоположных пар предсказатель, видящий только этот вектор, не может превысить 50% ожидаемой точности. Причина — одинаковый вход при разных требуемых ответах, а не нехватка обучения. Дополнительный доступ к истории, исходным данным или внешнему контексту изменил бы условие задачи.

## Точный контроль и его границы

Для вопроса «есть ли ошибочная позиция внутри заданного множества?» достаточно сохранить один бит на позицию. Всего 71 бит, то есть 9 байт с выравниванием. Полные 71 × 23-битные результаты TX1 занимают 205 байт. У маски не сохраняются остальные свойства TX1.

Проверены все 65 536 сочетаний восьмибитного состояния и области запроса, затем 100 000 случайных 71-позиционных случаев, включая пустые и очень маленькие области. Расхождений с прямым логическим просмотром нет.

Для точной поддержки любого будущего подмножества 71 бит необходим в худшем случае: два разных вектора можно различить запросом к единственной позиции, где они отличаются. Для заранее фиксированного вопроса может хватить одного бита ответа. Это простой подсчёт числа состояний, не новая теорема.

Негативные проверки сохранены: одинаковая маска не гарантирует одинаковый `policy_allow`; ответ на одну область нельзя автоматически переносить на другую. Нет доказательства подлинности, полноты внешнего источника или актуальности политики. Формирование маски всё ещё требует чтения состояния; сквозная экономия вычислений не измерена.

## Проверка воспроизводимости

Исходная реализация: `0b9da9e61eed562797473c8a841902247a2aa946`.
Код эксперимента и успешный CI: `6d004a20ae23fca9ad525693607ab8cbd7d903dd`.
GitHub: https://github.com/safal207/BardoCompute/pull/44
Успешный запуск: https://github.com/safal207/BardoCompute/actions/runs/33943876410

Локально Python 3.13.5; в GitHub — 3.11.16 и 3.13.15. В каждом окружении проходят пять исходных unit-тестов, восемь тестов стенда и полный стресс-эксперимент. Среди внутренних подслучаев — 512 проверок упаковки трёхлинейного кода. Это не тысячи независимых гарантий безопасности системы.

Агрегированные результаты и сгенерированные входные состояния совпали между окружениями. Некоторые хеши признаков с плавающей точкой отличаются между Python 3.11 и 3.13; внутри каждого окружения вывод о равенстве пар тот же. Эти хеши нельзя использовать как межверсионные идентификаторы семантики.

Первый CI остановился до тестов: поверхностное клонирование не содержало исходного коммита для сравнения. Исправлена глубина клонирования, повторный запуск прошёл. Полный прежний обучающий бенчмарк не перезапускался.

## Как показывать техническому инвестору

Демонстрация: показать два состояния с разными ответами, одинаковый HYBRID-вход, затем точный ответ компактного обычного контроля. Завершить не обещанием «нового CPU», а конкретной проверяемой продуктовой гипотезой.

Предлагаемое направление: слой, который сообщает, какие решения допускает сжатая трасса агента, а при недостатке данных запрашивает дополнительные свидетельства или возвращает HOLD. Интеграция с ATMAN/CaPU в этом эксперименте не реализована.

Следующий необходимый результат — реальный внешний процесс и независимые трассы: одинаково корректные реализации, учёт всех данных и метаданных, стоимости сканирования, задержек, повторных запросов, доли HOLD и неправильных разрешений. До такой проверки 95,61% нельзя превращать в обещание экономии облачного бюджета.

## Повторение из архива

В каталоге `reproduction` находятся исходные модули и лицензия. Python 3.11+:

```bash
cd reproduction
python -m pip install -e . pytest
python -m pytest -q tests/test_logos_learning.py
python -m unittest discover -s experiments/witness_completeness_v1 -p test_lab.py -v
python experiments/witness_completeness_v1/run_lab.py --output evidence/reproduced
python -c "import json; r=json.load(open('evidence/reproduced/result.json')); assert r['source_mode']=='FULL_PINNED_UPSTREAM'; assert all(x['bitmap_errors']==0 for x in r['overload'])"
```

В `evidence` сохранены JSON, девять полных репрезентативных пар, локальные журналы, исходные журналы двух CI-окружений и сведения об их сравнении. `MANIFEST.json` содержит SHA-256 каждого файла архива. Исходный код Bardo не модифицирован этим исследованием.
